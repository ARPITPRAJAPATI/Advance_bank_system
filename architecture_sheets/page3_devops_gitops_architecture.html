2. DECLARATIVE GITOPS & RELEASE ENGINE ArgoCD + Auto-Bumper
KubePay-CD Tag-Bumper Pipeline sed Automation
• Clones monorepo and executes precise Unix string substitution:
sed -i "s|image: aruhehe/kubepay-backend:.*|image: aruhehe/kubepay-backend:${TAG}|g" k8s/backend-deployment.yaml
• Verifies manifest changes using git diff --exit-code prior to committing.
The Infinite Loop Defense Mechanism Production Crucial
The Risk: If CD commits back to GitHub, webhook triggers CI again ➔ Infinite build loop!
Our 3-Layer Defense:
1. Git Commit Tag: CD writes git commit -m "Auto-bump image [skip ci]".
2. Jenkins SCM Regex: Configured MessageExclusion: (?s).*\[skip ci\].*.
3. Path Exclusion: Jenkins CI ignores all commits touching only k8s/.*.
ArgoCD GitOps Reconciliation Engine Namespace: argocd
• Single Source of Truth: Git repo defines desired state. ArgoCD monitors origin/main.
• Self-Healing (selfHeal: true): Manual kubectl edits or manual deletions are instantly reverted back to Git manifest spec within 180 seconds.
• Automated Pruning (prune: true): Deleted manifests in Git automatically clean up orphaned pods on AWS EKS.

🎯 Interview Defense: Why GitOps over Direct Kubectl Deploy? "Direct kubectl apply from Jenkins requires storing cluster admin kubeconfig inside CI agent — a massive security breach risk. GitOps with ArgoCD reverses control: the cluster pulls manifests from Git inside-out with zero external access tokens."
⚡ Solving the GitOps Infinite Loop: "When CD updates manifest tags and pushes to GitHub, it can trigger CI again. We solved this with 3 layers: [skip ci] commit flags, Jenkins regex message exclusions, and directory path filtering targeting k8s/.*."
🔒 Multi-Stage Shift-Left Security: "Security is enforced at 4 distinct gates: Trivy scans repo filesystem, SonarQube enforces clean code gates, OWASP checks CVEs against NIST NVD database, and Trivy scans container image layers before any image touches EKS."
